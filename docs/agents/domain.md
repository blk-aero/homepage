# Domain docs

This repository uses a single-context layout: `GLOSSARY.md` and `docs/adr/` at the repository root.

Before exploring a topic, read the root glossary and any ADRs that apply to that topic. If they do not exist, proceed without creating them solely for setup. Domain-modeling work can create them when terms or decisions are resolved.

Use glossary terms when naming domain concepts. If a needed concept is absent, check whether the proposed language is appropriate or whether there is a gap to discuss. Flag any conflict with an existing ADR instead of silently overriding it.
